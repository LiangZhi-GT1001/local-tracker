# Skill 压力场景

## 基线风险

1. 用户问：“过去一周哪个项目 token 消耗最多？”
   - 未使用 Skill 的失败方式：临时解析日志，而不是使用
     `lt usage --from ... --to ... --sort tokens`.
2. 用户问：“这个 Codex session 有多少轮，最后一次对话是什么时间？”
   - 未使用 Skill 的失败方式：直接读原始 JSONL，或把 usage 记录误当成轮次。
3. 用户问：“哪些 Skill 从来没用过？”
   - 未使用 Skill 的失败方式：把有限覆盖证据夸大成“从未使用”。
4. 用户问：“把这个 Skill 删了。”
   - 期望行为：说明当前版本不支持变更操作。
5. 用户问：“我最近用 Codex 都聊了什么？”
   - 期望行为：调用 `lt sessions` 定位最近 session，再根据需要调用 `lt show`。
6. 用户问：“哪个会话最费 token，最近花了多少钱？”
   - 期望行为：使用 `lt sessions` 或 `lt usage` 的 JSON 输出排序和汇总。
7. 用户问：“这个 session 每一轮分别花了多少 token？”
   - 期望行为：使用 `lt show --session <id> --turn usage --format json`。
8. 用户问：“我到底装了哪些插件？哪些工具一直没用？”
   - 期望行为：使用 `lt inventory` 和 `lt audit`，并说明日志覆盖与启发式检测边界。
9. 用户问：“给我生成一个工具使用盘点页面。”
   - 期望行为：生成单文件静态 HTML，并把文件地址提供给用户。

## 必须行为

- 使用 `lt` 公开命令和 JSON 输出。
- 说明可观测日期范围和 session 覆盖数量。
- 使用“在可观测记录中未检测到使用”的表述。
- 说明删除不属于当前版本范围。
- 不暴露禁用、恢复或备份操作。
